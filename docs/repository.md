# 仓库结构与职责

本仓库以 Claude Cage 为交付产品。当前桌面实现为 Swift 原生窗口、React 工作台和 Go 控制服务；界面框架尚未迁移。agent-vm 提供虚拟机与共享等基础能力，其独立命令和发行工具保留在仓库中，不作为 Cage 的另一条产品发布线。

## 整理目标：保留服务，逐步替换界面

最终迁移到原生 Go 界面时，继续使用现有控制服务及其环境、项目、终端和网络能力。先保持现有外观与行为，把业务资源从请求处理代码中分离，再逐步替换界面；当前不更换框架，也不同时拆网络状态管理。

```text
当前工作台 / 后续原生 Go 界面
              │ 本机认证接口、命令与状态流
              ▼
         Go 控制服务
              │
              ├── 环境运行、项目共享、终端会话
              ├── 客机浏览器与编辑器控制
              └── 网络授权与代理管理
```

原生界面可以先通过现有本机 HTTP、WebSocket 接口连接同一个服务，沿用认证与来源校验，避免同时重写服务或复制一套会话状态。独立 Go 包不依赖具体界面框架；业务流程的编排目前仍在 `workbench`，后续按实际调用关系整理，不预建通用框架或空接口层。

迁移时，窗口和页面负责展示与交互，控制服务继续持有运行资源。隐藏窗口、断开画面或切换页面不结束环境与终端，显式停止和关闭会话仍走服务。浏览器画面、终端绘制、剪贴板与系统集成需要适配新界面；虚拟机后端、主机 PTY 和 macOS 专用实现的跨平台工作另行推进。

具体的 Swift 桌面能力、VM / PTY / 进程与文件锁、路径与权限、代理后台及更新安装边界见[平台能力与原生界面迁移边界](design/platform-boundaries.md)。桌面桥接集中在 `ui/src/desktop.js`，代理进程的 macOS 实现位于 `internal/managedproxy/service_darwin.go`；当前不增加通用平台接口或新的宿主实现。

### 迁移前按服务行为验收

验收标准是：不启动 React 工作台和 Swift 窗口，环境、项目共享、终端与网络服务仍可独立运行、测试，并由另一个界面通过认证接口调用。

- **独立入口**：控制服务能自行启动、接受命令并返回状态，不依赖窗口初始化或页面回调来完成业务操作。
- **资源归服务所有**：服务负责进程创建、状态维护与停止。界面只提交操作和订阅结果，断开界面连接不结束环境、项目共享或终端。
- **生命周期一致**：关闭会话、停止环境和应用更新仍按既有规则清理资源；作业取消、旧结果保护和人工暂停规则由服务执行。
- **无窗口验证**：通过服务命令与接口检查启动、连接、共享、会话、断开重连和停止；真实 VM 与网络行为需要在独立测试环境验收，不能只以包测试或目录拆分代替。

当前已有 `cage serve` 独立控制服务入口，环境运行、项目共享、终端、浏览器连接、设置和作业调度已有独立模块。`workbench.Service` 持有运行资源与业务状态，`workbench.Server` 持有 HTTP 会话和认证票据；环境与设置命令已有不接收 HTTP 请求的入口。网络状态管理仍在原来的工作台实现中，保持整体归属与判断顺序。

## 从正确的入口开始

以下命令均在仓库根目录执行。

| 要完成的工作 | 入口 | 产物或影响 |
|---|---|---|
| 查看开发命令 | `make help` | 列出 Cage 与保留的上游入口 |
| 构建控制程序和工作台资源 | `make` 或 `make cage` | `_output/bin/cage`，不是完整 App |
| 构建 macOS App | `make app` | 先检查 Go 许可，再生成 `_output/Cage.app`，默认本地 ad-hoc 签名 |
| 构建并安装 macOS App | `make install-app` | 安装到 `~/Applications/Cage.app`；替换与清理规则见贡献指南 |
| 制作正式安装包 | `make package-app` | 签名、公证与安装包；需要发布凭据，见发行指南 |
| 检查 Go 代码 | `make test` | Go 测试；界面、原生更新和集成检查见贡献指南 |
| 检查工作台、客机辅助程序与构建工具 | `make test-ui test-guest test-tools` | 各模块的本地检查；前端依赖先运行 `npm ci --prefix ui` |
| 运行真实 VM 的无窗口完整验收 | `make test-headless HEADLESS_UPSTREAM=socks5://127.0.0.1:<已授权端口>` | 新建独立配置、用户目录、项目与 VM；条件与结果见[验收说明](headless-acceptance.md) |
| 更新或检查 Go 许可 | `make licenses` / `make check-licenses` | 显式更新生成文件，或只读校验 |
| 检查下载的 macOS 发行物 | `make verify-release RELEASE_DIR=<目录>` | 核对摘要、签名、公证票据与版本，不安装 App |

常用操作统一由 Makefile 调用已有脚本；底层脚本仍可直接使用。`make` 和 `make install` 的原有含义保持不变。构建与安装的完整要求见[参与开发](../CONTRIBUTING.md)，正式发行见[发布 macOS 安装包](releasing.md)和[公开发行与主页部署](public-releases.md)。打包不等于向 GitHub 发布。

## 工作台职责拆分

按持有的数据和运行资源确定边界，逐项迁移；本轮保留 Swift、React 和现有 HTTP 接口。当前归属与后续顺序如下，待拆部分仍使用现有实现，不预建空包。

| 职责 | 当前实现与数据 | 整理方向 |
|---|---|---|
| 项目授权与共享 | `internal/projects/`；持有 `projects.json`、共享子进程和传输管道 | 已独立；工作台只提供已有的客机命令连接并调用项目接口 |
| 环境身份与生命周期 | `internal/environment/` 持有 `environment.json` 与运行命令；`workbench/environment.go` 协调完整操作流程 | 运行部分已独立；界面就绪状态、作业、网络授权和会话协调继续归工作台 |
| 网络授权与复检 | `workbench/safety.go`、`network_intent.go`、`proxy.go` 及环境流程中的网络检查；`cage/gate*.go`、`egress.go`；`network-intent.json` | 本轮不拆；保留网络门槛、暂停版本与取消规则的整体性 |
| 终端会话 | `internal/terminal/` 持有子进程、会话与输出；`workbench/terminal_service.go` 编排业务，`terminal.go` 适配请求 | 服务负责环境检查、项目授权、共享与会话创建；HTTP 与 WebSocket 不进入会话模块 |
| 浏览器与编辑器 | `internal/browser/` 连接客机控制器；`workbench/browser_service.go` 编排业务，`browser.go` 适配请求；客机源码在 `internal/cage/guest/` | 服务持有就绪状态、默认网站偏好、项目授权和订阅寿命；HTTP 层保留认证与传输，画面转发仍在 `workbench/vnc.go` |
| 设置与应用流程 | `internal/settings/` 持有设置模型、校验和存储；`workbench/settings.go` 适配请求，`settings_apply.go` 编排应用 | 模型与存储已独立；工作台继续持有当前偏好、作业与运行状态，协调网络判断和环境操作 |
| 外观与收藏 | `workbench/appearance.go`、`favorites.go`；`appearance.json`、`favorites.json` | 独立于环境设置，保持现有持久化与接口，不触发环境重启 |
| 作业调度与执行上下文 | `internal/jobs/` 持有当前作业、取消函数与执行上下文；`workbench/jobs.go` 负责业务准入与停止准备 | 已与 HTTP 分开；同步操作和监测仍共用原有环境操作锁，网络意图留在工作台 |
| 服务命令与状态读取 | `workbench/service.go` 持有业务状态与环境、设置命令；`snapshot.go` 返回状态副本 | 环境与设置 HTTP 入口调用同一 `Service`，不另建一份运行状态 |
| 认证与请求入口 | `workbench/server.go`、`control_lifecycle.go`、`jobs_http.go` | 保留认证、路由与响应适配，调用已有业务入口 |

### 服务资源与 HTTP 对象

`Service` 是单份配置的资源持有者，包含环境就绪状态、客机凭据、项目与终端管理器、浏览器客户端、作业队列和现有网络状态。`Server` 引用同一个服务对象，持有启动密钥、会话、入口票据和 HTTP 关闭回调。环境、项目共享、作业和网络方法归 `Service`；网络实现本轮只调整接收者，未拆分状态机或改变规则。

`Service.Start`、`Stop`、`ReadSettings`、`SaveSettings`、`ProbeSettings`、`RestoreSettings`、`UpdateComponents` 和 `UpdateTools` 提供有明确输入与返回值的业务入口，环境与设置 HTTP 处理器只解析请求、调用这些入口并返回结果。终端与浏览器另有 `CreateTerminal`、`CloseTerminal`、`Terminals`、`Terminal`、`BrowserTabs`、`BrowserCommand` 和 `SubscribeBrowser`，不接收 HTTP 对象。校验、项目作业分类、暂停版本和恢复顺序继续在服务中执行，直接调用服务也不能绕过校验。作业继续在原有环境操作锁下异步执行。

`Service.Snapshot` 返回有明确字段的状态副本，沿用 `/api/status` 的完整 JSON 格式，不加入工具或客机版本探测。位置、网络检查报告及其检查列表均复制后返回，调用方修改快照不会改变服务状态；客机令牌和 VNC 密码不进入快照。网络检查仍使用实际管理地址验证认证与端口隔离，该地址作为服务运行信息保留，不依赖窗口或页面。

`OpenService` 取得配置控制锁、初始化服务并启动监测，调用方负责执行 `Close`。`ServeContext` 在同一个服务上提供 HTTP 监听、认证和控制记录，接收宿主取消信号；原有 `Serve` 入口继续使用，并将 SIGINT、SIGTERM 转为同一退出流程。后续原生界面优先复用这个控制服务；服务对象内的方法供受信任的进程内调用，远程调用继续通过已有认证接口。

`service_test.go` 在不创建 `Server`、HTTP 请求或窗口的情况下，验证设置读取与保存、作业完成、真实本地终端进程的保留与停止、排队启动被停止抢占，以及直接调用的校验和状态快照。真实 VM 启停、恢复和完整联网检查仍需在独立测试环境验收。

终端与编辑器的服务测试还验证直接创建与关闭会话、默认网站、指定目录不改变当前项目、目录授权与操作互斥，以及服务退出后拒绝新操作。直接浏览器订阅也随服务退出释放，不要求调用方先关闭 HTTP 宿主。

### 界面、环境与控制服务的生命周期

三类关闭操作有不同的资源范围：

| 操作 | 结束什么 | 保留什么 |
|---|---|---|
| 关闭界面或断开订阅 | 当前显示、终端或事件订阅连接 | 控制服务、已接受的作业、终端进程、项目共享和 VM |
| 停止环境 | 取消现有作业，按原流程关闭网络、终端、项目共享与 VM；成功后停止独立代理 | 配置、磁盘和项目授权；控制服务继续接受操作 |
| 退出控制服务 | 拒绝新操作，取消并等待作业、监测和在途请求结束，关闭网络门槛、主机终端、共享与浏览器连接，停止独立代理 | VM 与磁盘、配置和持久网络意图；再次启动服务后重新连接 |

服务持有统一取消上下文。后台环境监测、网络监测及非作业控制调用使用该上下文；作业继续使用自己的执行上下文，由退出流程统一取消并等待。关闭 HTTP 请求或窗口不会取消已接受的作业。清理网络门槛仍使用原有的有超时关闭操作，不因服务上下文已取消而跳过。

HTTP 请求与服务退出关联，终端和画面 WebSocket 在退出时主动关闭；浏览器事件连接随上下文结束。终端与共享管理器等待其子进程回收，作业队列也等待被停止操作替代、仍在排队的旧工作结束。`Close` 可重复调用，清理完成后才删除本服务发布的 `control.json` 并释放配置控制锁。空闲更新接管与宿主取消使用同一清理流程，窗口关闭不调用 `Close`。

`lifecycle_test.go` 验证服务取消、作业和请求排空、监测请求中止、断开界面后终端保留、退出时流与本地子进程关闭、初始化失败释放锁，以及 HTTP 宿主取消和空闲更新接管。VM 保留与网络意图使用本地运行标记和网络门槛检查；真实 VM 的退出与重连仍需在独立测试环境验收。

### 项目模块的实际边界

```text
workbench ──→ projects ──→ mounts / privatefile / reversesshfs
    │            │
    │            └── Guest：通过工作台提供的既有 SSH 连接运行命令
    └── HTTP 认证、作业编排、当前项目偏好与状态响应
```

`projects` 不导入工作台、HTTP、React 或 Swift。`Guest` 只提供客机命令执行和共享子进程创建，工作台将调用交给 `environment` 的既有 SSH 实现。共享连接由项目模块持有，切换项目复用已有连接，停止环境时统一关闭，重新连接环境时恢复保存的目录。

配置归属保持稳定：`environment.json` 记录唯一环境的身份；`projects.json` 保持原有 `paths` 数组格式，记录明确打开的目录；`workbench.json` 继续保存当前项目与偏好。默认目录和旧配置中的当前目录仍按原规则补入项目列表。项目请求仍需通过目录授权和路径校验，不能共享控制配置或版本控制元数据目录。

项目测试分两层：`internal/projects/` 验证共享资源生命周期、配置恢复以及真实 SFTP 的目录隔离；`internal/workbench/` 验证项目切换不重启环境、不结束旧终端，以及终端与编辑器请求使用明确授权的目录。共享生命周期测试使用本地子进程代替 SSH，不要求启动日常 VM；真实客机挂载仍需独立环境验收。

### 环境运行与工作台编排

修改虚拟机命令、环境目录或组件读取时，从 `internal/environment/` 开始；修改“何时关闭外网、发布就绪状态或结束会话”时，从 `internal/workbench/environment.go` 开始。

`environment.Runtime` 使用固定配置路径和可执行文件执行操作，不持有工作台状态，不导入 HTTP 或界面代码。`Operation` 传入已有作业编号、日志输出和进度回调，每条控制命令继续受作业取消和 30 分钟超时约束。环境目录仍由 `cage.EnvironmentDir` 统一解析，供 CLI 和工作台共用；旧 VM 的迁移与 `environment.json` 格式保持不变。客机连接结果按次返回，工作台仍是就绪状态和凭据的唯一持有者。

完整操作的顺序如下：

1. **启动**：工作台先检查本机 Git、目录和代理配置，尝试连接已有环境。需要启动时沿用原有出口检查、时区与语言处理，再调用 `Runtime.Start`；基础环境尚未安装时依次执行 `setup`、`up`，否则只执行 `up`。随后沿用最多 8 次连接尝试，成功后执行原有网络检查。
2. **连接**：`Runtime.Connection` 检查 VM 存活状态，通过受限 SSH 读取凭据与组件清单；工作台再检查浏览器健康、设置默认页，随后发布就绪状态并恢复项目共享。清单缺失或不匹配时继续显示需要更新，并关闭外网。
3. **停止**：显式停止先取消正在运行的作业并请求停止其 VM 构建；操作进入队列后关闭网络门槛，清除连接状态、关闭终端与共享，再调用 `Runtime.Stop` 停止已有 VM。只有显式停止成功后才停止独立代理，设置变更等内部重启保留原有代理规则。
4. **组件更新**：先确认 VM 运行并关闭网络门槛，标记组件更新未完成，再调用与启动共用的 `Runtime.ApplyComponents` 执行 `up`。重新连接成功后，人工暂停状态保持不变；未暂停时再走原有网络检查。更新失败保留未就绪状态和可重试提示，不关闭工作台终端。

工具升级所需的网络放行、有效期和续租判断仍在 `workbench/environment_versions.go`，本轮不拆网络逻辑。组件和工具版本的客机探测移至 `environment.Versions`，代理核心版本、更新权限及 HTTP 响应仍由工作台组装；周期状态查询不会新增工具探测。

环境包测试使用临时配置和真实本地子进程验证命令顺序、参数传递、取消、失败中止和停止条件；组件清单校验测试随实现迁入。工作台测试继续覆盖 SSH 隔离、旧环境保留、停止抢占和网络暂停，并验证组件更新失败时关闭外网、保留会话。真实 VM 的启动、重连和组件更新仍需在独立测试环境验收。

### 终端会话与界面连接

`terminal.Manager` 持有终端进程和会话列表，`Session` 提供输入、尺寸调整、状态与输出订阅；不导入 HTTP、WebSocket 或工作台。工作台先校验环境状态和项目授权、建立共享，再将 `environment.Runtime.TerminalCommand` 创建的受限 SSH 命令交给会话模块运行。SSH 仍连接配置对应的固定 VM，不继承主机环境或开放本机命令与代理转发。

每个会话保留最近 512 KiB 输出。订阅同时取得历史快照和后续输出，页面重连不重启进程；关闭订阅只断开该客户端，慢客户端不阻塞终端。最多保留 12 个会话，已结束的会话也占用名额；显式关闭会话才移除记录，停止环境保留已结束会话及历史供页面读取。控制服务重启后不恢复旧会话。

`workbench/terminal_service.go` 负责环境运行检查、操作互斥、目录授权、共享准备和终端创建。创建与关闭登记为服务活动，退出后拒绝新操作。`Terminal` 返回现有会话，调用方使用其输入、尺寸和订阅能力；订阅关闭不结束会话。`workbench/terminal.go` 保留原有 HTTP 路径、JSON 字段、WebSocket 输入与尺寸消息和二进制输出，只做请求与传输适配。停止环境通过 `CloseAll` 结束终端；项目切换和组件更新不关闭终端，后台更新接管仍拒绝存活会话。VNC 转发独立放在 `workbench/vnc.go`，不归终端模块管理。

终端包用真实本地 PTY 子进程验证输入、尺寸、断开与重连、输出上限、慢订阅、退出回收和会话名额；工作台通过真实本机 WebSocket 验证认证、协议及历史重放，并保留项目、停止和更新接管的集成检查。这些检查不启动日常 VM。

### 浏览器控制与事件订阅

修改客机控制请求及连接行为时，从 `internal/browser/` 开始；环境就绪判断、新标签默认网站和编辑器目录授权归 `workbench/browser_service.go`；请求认证与传输适配归 `workbench/browser.go` 和 HTTP 入口。标签、下载和编辑器页面的实际状态仍由客机 `browser-agent.mjs` 管理，主机客户端不保存另一份浏览器状态。

`browser.Client` 提供标签读取、固定动作的 `Command`、默认网站设置、健康检查、诊断和 `Subscribe`。它不依赖工作台、React、Swift 或 HTTP 请求处理器；内部使用 HTTP 连接客机控制器。工作台继续指定原有的 `http://127.0.0.1:18500`，地址不来自页面输入或配置。请求使用本次操作的客机凭据，不转发工作台会话、Cookie 或 Origin；禁用环境代理并拒绝重定向。普通命令、诊断、编辑器恢复分别保留 5、20、30 秒超时。

`workbench/browser.go` 保留 `/api/browser/tabs`、`/api/browser/{action}` 和 `/api/browser/events` 的方法、载荷与业务错误状态码。请求先解析，再交给服务执行。新建标签未传地址时，服务使用工作台默认网站；编辑器打开与恢复在环境操作锁下校验项目并建立共享，再发出客机命令。`BrowserRequestError` 区分客机请求失败与本地校验失败，不包含 HTTP 状态码。健康检查和默认网站应用仍由环境连接流程调用，浏览器诊断仍由原有网络检测流程调用，不改变网络授权判断。

浏览器客户端的 `Subscribe` 返回一条可读取、可关闭的客机 SSE 事件流，沿用调用方的取消上下文。服务的 `SubscribeBrowser` 加入就绪检查、服务取消和活动清理，调用方关闭、上下文取消或服务退出均释放该订阅。初始状态、后续状态与心跳原样传递，未知字段也保留；HTTP 适配层只负责设置事件响应头并及时发送数据。关闭订阅不关闭标签页或其他订阅。Go 客户端不额外重连、缓存或重放事件；现有工作台继续由 `EventSource` 重连并取得客机当前快照。VNC 画面连接与控制事件仍分开管理。

浏览器包通过本机 HTTP 服务验证动作、凭据、载荷、超时、失败响应和拒绝重定向，并验证多个事件订阅的独立关闭及取消。工作台检查覆盖认证与错误状态、完整 SSE 转发、页面断开后的连接释放，以及原有文字输入、下载重试、项目目录和默认网站行为。真实客机浏览器验收仍使用已有冒烟检查。

### 前端连接与状态归属

`ui/src/workbench-connection.js` 管理会话初始化、状态轮询、设置刷新和唯一浏览器事件订阅；`use-workbench.js` 只将这些更新交给 React。服务快照是环境、作业、项目与终端列表的来源，客机事件与快照是浏览器状态的来源。`main.jsx` 保留当前页、当前标签、地址栏草稿、对话框和标签组合；本地名称、置顶与排序仍由既有偏好文件和本地存储管理，不作为项目授权或进程状态。

轮询沿用作业执行中 1.2 秒、窗口可见时 3 秒、隐藏时 15 秒的间隔；窗口恢复可见时立即刷新。浏览器事件连接由 `EventSource` 自动重连，未连通时继续通过轮询读取浏览器快照。若读取快照期间收到新事件，较旧的响应不会覆盖新事件。请求认证与一次会话续期重试集中在 `api.js`；连接关闭时取消自己的请求，但不取消其他调用方共用的会话续期，也不在取消后重发请求。

`terminal-connection.js` 负责终端 WebSocket 协议与连接清理，`views.jsx` 负责终端绘制、尺寸与交互。终端沿用手动重连，每次重建终端视图并读取服务保留的历史，避免自动重连重复追加历史。切换标签保留终端连接，移除视图只关闭订阅，不发送关闭会话命令。

`display-connection.js` 管理 noVNC 连接、凭据请求、原有 1–5 秒退避重连、尺寸请求与输入资源。浏览器画面隐藏或原生窗口不可见时关闭显示连接，恢复可见时重新连接；不结束客机浏览器或环境。页面卸载会清理轮询、事件订阅和已挂载的视图连接，旧连接回调不会再更新新视图。设置面板自身的按需读取与代理诊断轮询仍归对应面板，不引入全局事件总线。

### 设置校验、保存与应用

`internal/settings/` 提供 `Preferences`、请求与响应使用的 `Values`、备份使用的 `Profile`，以及文件存储 `Store`。`View` 返回原有设置字段，不包含代理地址和凭据；`Propose` 沿用配置、按键、默认网站和项目路径校验，保留当前代理来源与旧表单未传入的出口规则。`cage.Config` 仍是环境配置的统一类型，项目路径继续由 `projects` 校验。

`Profile.RequiresRestart` 统一保存入口和应用流程的判断：环境配置、自动时区或自动语言改变时需要重启；仅修改项目、按键或默认网站时不重启。工作台仍持有已应用的偏好；`workbench.Preferences` 和 `workbench.Settings` 保留原有类型入口。

`Store` 读写原有配置路径、`workbench.json` 和 `previous-profile.json`，不改变字段、文件名或 `0600` 权限。启动读取保留旧偏好的默认值处理。保存先写环境配置，再写偏好；偏好写入失败时尝试恢复原环境配置。每个文件继续通过 `privatefile` 原子写入，两个文件沿用原有顺序，不构成跨文件事务。备份读取仍只检查文件与 JSON 能否读取，不新增恢复前提。

`workbench/settings.go` 负责 `/api/settings`、`/api/settings/probe` 和 `/api/restore` 的请求解析与错误响应，调用 `Service` 的设置命令；`workbench/settings_apply.go` 协调完整应用流程：保留当前代理来源，按原规则探测和验证出口，检查暂停版本与取消状态，备份旧配置后停止环境，处理项目共享，保存配置与偏好，最后更新内存状态并应用默认网站或重新启动环境。恢复继续走同一应用流程和现有启动入口。作业队列、停止抢占、旧作业结果保护和网络授权逻辑没有迁移到设置包。

位置探测及其数据结构仍归工作台，集中于 `workbench/location.go`，沿用原有代理传输与响应校验。设置包不发起网络探测、不控制 VM，也不依赖 HTTP 或界面框架。

原有默认网站、私有目录与出口规则校验测试随实现迁入设置包；存储测试覆盖旧偏好读取、完整配置保存、备份格式、权限和失败回退。工作台继续验证项目切换、默认网站和按键不会重启环境、较晚的人工暂停不会被旧设置任务清除，并检查设置保存沿用作业队列、存储失败会中止后续操作。

### 作业调度与执行上下文

`jobs.Queue` 只保留最新作业，接受一个待执行或执行中的操作。作业先被接受，再异步等待原有环境操作锁；普通操作遇到忙碌状态仍被拒绝，停止操作取消并替代旧作业，重复停止返回同一个作业。已经被替代的待执行回调不会运行。作业状态与取消函数归调度器所有，同步编辑器操作、终端创建和后台监测继续使用同一把环境操作锁。

`jobs.Execution` 提供本次作业的编号、取消上下文、进度与日志写入。作业寿命独立于提交请求：HTTP 请求结束或界面断开不取消已接受的操作。停止或显式取消通过调度器取消上下文，业务操作继续按原有方式响应取消。环境命令取得的输出与进度回调绑定原作业；旧命令在停止期间或结束后输出，都不能覆盖新作业的进度、日志或结果。日志仍保留最近 24,000 字节，成功、失败、取消仍使用原有结果字段与提示。未处于作业中的工作台控制调用使用服务取消上下文。`Queue.Close` 拒绝后续提交、取消已接受的工作，并等待全部工作结束。

`workbench/jobs.go` 的 `submit` 是业务提交入口，负责后台接管状态、网络恢复意图、暂停版本和监测取消。准入保持先取得工作台状态锁、再取得调度器锁的顺序；准备步骤在接受操作时执行，失败不发布新作业。网络意图的持久化、暂停版本比较、代理门槛和工具更新续租规则仍在原来的工作台网络实现中，调度器不持有这些状态。停止前请求取消客机构建和关闭外网的顺序也保持不变。

`workbench/jobs_http.go` 只将提交结果转换为 JSON 或既有的 400、409、503 错误；`workbench.Job` 保留原有类型入口，`/api/status` 继续返回原有作业字段。自动物理网卡恢复与订阅更新直接调用 `submit`，不再构造丢弃内容的 HTTP 响应对象。

作业包无需界面或 HTTP 即可测试执行、等待操作锁、拒绝忙碌提交、停止抢占与复用、执行前取消、准备失败、日志上限和过期输出保护。工作台测试使用真实提交的作业建立忙碌状态，继续覆盖停止结果、网络暂停、监测续租与后台接管，并验证取消设置请求的上下文不会中断已排队的保存任务。

## 客机资源与主机代码的边界

`internal/cage/guest/` 是资源目录，不是独立 Go 包。浏览器控制程序的模块引用以及 JavaScript/Python 测试保持同目录关系；运行时资源由 `guest_resources.go` 逐项嵌入，测试文件不随程序嵌入。
