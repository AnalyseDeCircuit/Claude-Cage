# 无窗口完整验收

这项验收直接启动候选 `cage serve`，通过认证后的服务接口、真实终端 WebSocket 和浏览器事件流操作独立 VM。不打开 React 页面，不启动 Swift App，不使用模拟客机或替代服务。

## 准备候选程序和测试上游

需要可运行 VM 的 macOS 主机、Go 与 Node.js 构建环境，以及明确获准使用的本机 SOCKS5 代理。首次初始化会下载 Debian 镜像与客机工具，需要网络、磁盘空间和数分钟至更长时间。

```sh
make proxy-core cage
make test-headless HEADLESS_UPSTREAM=socks5://127.0.0.1:<已授权的代理端口>
```

`HEADLESS_UPSTREAM` 必须显式传入，不读取日常 Cage 配置、订阅或节点密码。代理上游只接受不含凭据的本机 SOCKS5 地址；可以使用获准的现有代理软件本机端口，不会修改或重启该软件。测试专用 Cage 代理使用另一个端口与独立后台进程。

已有候选程序时指定路径，不重新构建或安装日常 App：

```sh
make test-headless \
  HEADLESS_CAGE=/绝对路径/cage \
  HEADLESS_UPSTREAM=socks5://127.0.0.1:<已授权的代理端口> \
  HEADLESS_REPORT=/绝对路径/验收报告目录
```

候选程序需要嵌入真实 Lima 客机资源，在 macOS 上带有虚拟化所需签名权限，并能通过现有 `CorePath` 规则找到同构建准备的 Mihomo。构建入口负责这些条件，验收脚本不更换可执行文件或借用其他 App 的二进制。

若镜像长连接下载中断，可以显式指定 `HEADLESS_IMAGE_CACHE=/绝对路径/Lima镜像缓存`，把已准备的镜像缓存复制到本次独立用户目录。候选程序仍按自身模板校验镜像摘要，不修改模板或写入伪造的校验记录；VM、密钥、配置和项目仍全新创建。报告的 `image_cache` 会记录这个输入。使用缓存完成的验收，不包含首次镜像自动下载成功这一结论。

## 独立环境如何隔离

执行入口为 `scripts/tests/headless/main.go`，由 Make 调用。每次在短路径 `/tmp/cage-hl-*` 下创建新的私有配置、用户目录、项目、Lima 状态与 VM，避免 Unix socket 路径过长。

- `HOME`、Git 全局配置、Cage 配置和 VM 状态均指向测试目录。Git 安全设置只写入测试用户目录，不修改用户的全局配置。
- 不继承主机代理变量、既有 VM 状态变量或 Claude 登录凭据。只共享本次创建的测试项目。
- 当前客机控制仍使用固定的 `15900`、`16080`、`18080`、`18500` 端口。任一端口已占用时，验收在启动服务前失败，不停止占用者。这也意味着当前完整客机环境不能靠另建配置就随意并行启动。
- 进程信号仅发送给验收自己启动的控制服务。停止命令始终使用本次新建的配置，不依据外部 PID 记录终止进程。

## 验收覆盖的实际流程

1. 不加载界面，启动真实控制服务，取得一次性入口并建立会话；未认证请求仍被拒绝。
2. 导入唯一测试节点、应用独立代理端口，执行原有代理连通检查。
3. 通过服务启动真实 VM、安装客机组件，并通过既有网络检查取得有效放行。
4. 通过设置服务打开测试项目，建立真实共享连接。
5. 创建真实 SSH 终端，经 WebSocket 写入项目文件；主机验证内容。断开客户端后，客机后台工作继续完成；重新连接读取历史，并确认仍是原 shell 会话。
6. 通过服务打开指定项目的编辑器；两次独立订阅浏览器事件都能看到该编辑器。另从真实客机检查编辑器健康与共享文件内容，再建立新的控制会话。
7. 在 VM 运行时退出控制服务，确认 VM 保留；重新启动控制服务，确认旧主机终端不被伪恢复，并能重新连接浏览器、编辑器与项目。
8. 再创建终端，通过服务停止环境，确认 VM、终端和连接结束，控制服务仍可接受请求。
9. 执行空闲接管退出，再启动同一配置，确认控制锁释放、项目持久化且已停止的 VM 不会自行启动，最后退出服务。

测试不以“请求已接受”代替完成：作业必须是同一个已接受的编号并成功结束；终端文件必须实际出现在主机共享目录；事件必须来自真实客机；终端连接超时不能当作已经关闭。

## 阅读结果与处理失败

默认结果写入 `docs/test-reports/headless-<时间>/result.json`，可用 `HEADLESS_REPORT` 指定目录。报告记录每个步骤的结果、耗时、请求路径、候选程序路径、独立环境位置和清理结果，不写控制票据或代理认证信息。私有控制日志与完整作业记录留在测试目录，权限为 `0600`，不要公开上传。

任一步失败，整体验收失败。脚本仍尝试停止本次 VM、退出本次控制服务；清理失败会单独报告，并保留现场。正常结束也保留已停止的测试磁盘与配置供复核，不自动删除磁盘。检查报告中的 `cleanup` 和 `test_root` 后，再决定是否清理该独立目录。

这套验收确认真实服务的无窗口流程及其已有网络门槛。Claude 账号登录、模型调用、原生输入法、界面显示和安装更新属于各自验收范围，不通过本流程代替验证。
